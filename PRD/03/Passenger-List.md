# PRD Passenger List UI/UX

**هدف:** طراحی رابط کاربری برای مشاهده، انتخاب و مدیریت (افزودن، ویرایش، حذف) لیست مسافرانِ ذخیره‌شده توسط کاربر، جهت تسریع در فرآیند رزرو بلیت، پرواز و تور.

---

## 1. هدف و دامنه محصول
این صفحه/بخش به کاربر اجازه می‌دهد تا مسافرانی که قبلاً اطلاعاتشان را ثبت کرده است مشاهده کند، آن‌ها را برای رزرو جدید انتخاب کند، مسافر جدید اضافه کند و یا اطلاعات مسافران قبلی را ویرایش یا حذف نماید.

### 1.1 اهداف اصلی
- دسترسی سریع به لیست مسافران پرکاربرد برای جلوگیری از ورود مجدد اطلاعات
- پشتیبانی از کاربران **ایرانی** و **غیر ایرانی**
- امکان افزودن، ویرایش و حذف مسافر با کمترین اصطکاک (Friction)
- نمایش وضعیت مسافران در یک نگاه
- یکپارچگی کامل با منطق فرم "اطلاعات پروفایل" (تفکیک ملیت، تاریخ‌ها و...)
- کاهش خطای ورود اطلاعات با استفاده از راهنمایی‌های UX و Validation

### 1.2 اصول طراحی
- کاربر باید در نگاه اول یک لیست مرتب از مسافران را ببیند.
- عملیات اصلی (ویرایش/حذف/انتخاب) باید به راحتی در دسترس و قابل درک باشند.
- فرم باید ساده، قابل فهم و کم‌خطا باشد.
- فیلدهای مرتبط باید در گروه‌های منطقی دسته‌بندی شوند.
- تفاوت بین فیلدهای مشابه باید با متن راهنما و UI شفاف شود
- در مواردی که اطلاعات بر اساس ملیت متفاوت است، UI باید این تفاوت را به‌صورت واضح نمایش دهد

## 2. اطلاعات مورد نیاز کاربر
فرم باید اطلاعات زیر را از کاربر دریافت کند:

- نام
- نام خانوادگی
- کد ملی
- جنسیت
- تاریخ تولد
- ملیت
- کشور
- شماره پاسپورت
- تاریخ انقضای پاسپورت

## 3. نیازمندی‌های عملکردی (مدیریت لیست)

### 3.1 مشاهده لیست (List View)
- سیستم باید مسافران ثبت‌شده را به‌صورت کارت (Card) یا ردیف (Row) نمایش دهد.
- در صورت خالی بودن لیست، باید یک **Empty State** جذاب همراه با دکمه "افزودن اولین مسافر" نمایش داده شود.

### 3.2 افزودن مسافر جدید (Add Passenger)
- دکمه "افزودن مسافر جدید" باید همیشه در دسترس و کاملاً واضح باشد.
- با کلیک روی این دکمه، فرم ثبت اطلاعات در قالب یک Modal، Bottom Sheet یا صفحه جدید باز می‌شود.

### 3.3 ویرایش مسافر (Edit Passenger)
- هر مسافر در لیست باید دکمه/آیکون **ویرایش (Edit)** داشته باشد.
- با کلیک روی ویرایش، همان فرم اطلاعات باز می‌شود در حالی که مقادیر قبلی در آن پُر شده است (Pre-filled).

### 3.4 حذف مسافر (Delete Passenger)
- هر مسافر در لیست باید دکمه/آیکون **حذف (Delete)** داشته باشد.
- برای جلوگیری از خطای کاربر، با کلیک روی حذف، باید یک **پنجره تایید (Confirmation Modal)** باز شود (مثلاً: "آیا از حذف [نام مسافر] اطمینان دارید؟").

### 3.5 اطلاعات هویتی (Identity Information)
- فرم باید فیلدهای **نام** و **نام خانوادگی** را به‌صورت Text Input دریافت کند.
- فیلد **جنسیت** باید فقط شامل دو گزینه باشد:
 - مرد
  - زن
- فیلد **کد ملی**:
 - این فیلد **فقط برای کاربران ایرانی** نمایش داده می‌شود.
 - اگر ملیت «ایرانی» انتخاب شود، این فیلد باید در فرم ظاهر شود.
 - اگر ملیت «غیر ایرانی» انتخاب شود، این فیلد باید **مخفی (Hide)** شود.
- فیلد **تاریخ تولد** باید بر اساس ملیت کاربر نمایش و دریافت شود:
  - برای کاربران **ایرانی**: تاریخ **شمسی**
  - برای کاربران **غیر ایرانی**: تاریخ **میلادی**
- نحوه نمایش تاریخ تولد باید برای کاربر کاملاً شفاف باشد و فرمت تاریخ در UI مشخص شود.

### 3.6 ملیت و کشور (Nationality / Country)
- فیلد **ملیت** باید به‌صورت **لیست بازشونده (Dropdown)** طراحی شود.
- کاربر باید بتواند ملیت خود را از لیست انتخاب کند.
- در UI باید به‌وضوح مشخص باشد که این فیلد قابل انتخاب از لیست است.
- در طراحی این بخش باید سناریوی **ایرانی / غیر ایرانی** در نظر گرفته شود.
- در صورت نیاز، بعد از انتخاب ملیت، سایر فیلدهای وابسته می‌توانند بر اساس آن رفتار متفاوت داشته باشند.

### 3.7 محل صدور ویزا (Visa Issuing Country)
- فیلد **محل صدور ویزا** باید جدا از ملیت نمایش داده شود.
- باید برای کاربر کاملاً خوانا باشد که:
  - **ملیت**
  - **محل صدور ویزا**
  
  ممکن است با هم متفاوت باشند.
- برای جلوگیری از برداشت اشتباه، زیر این فیلد باید متن راهنما نمایش داده شود.
- این فیلد باید برای سناریوهای آینده مانند **مسافر خارجی** و **بلیط هواپیما** نیز قابل استفاده باشد.

### 3.8 شماره پاسپورت (Passport Number)
- فرم باید فیلد **شماره پاسپورت** را دریافت کند.
- این فیلد برای پروازهای خارجی ضروری است.
- ورودی این فیلد باید به شکلی باشد که کاربر تشخیص دهد منظور شماره پاسپورت است.

### 3.9 تاریخ انقضای پاسپورت 
- فرم باید **تاریخ انقضای پاسپورت**  را دریافت کند.
- تاریخ باید **به‌صورت میلادی** دریافت شود.
- نحوه نمایش و انتخاب تاریخ باید برای کاربر واضح  باشد.

## 4. نیازمندی‌های UX و رفتار رابط کاربری

### 4.1 معماری صفحه
- **حالت پیش‌فرض:** لیست مسافران + دکمه افزودن.

### 4.2 خوانایی و علائم بصری (Visual Cues)
- استفاده از آیکون برای نشان دادن **جنسیت** (مرد/زن).
- استفاده از تگ‌های رنگی یا Badge برای نشان دادن **رده سنی** (بزرگسال، کودک، نوزاد) که در محاسبات قیمت تور و پرواز مهم است.

### 4.3 نمایش وابسته به ملیت
- **ملیت ایرانی:**
    - نمایش فیلد **کد ملی** (الزامی).
    - نمایش تقویم با فرمت **شمسی** برای تاریخ تولد.
- **ملیت غیر ایرانی:**
    - **مخفی کردن فیلد کد ملی** (این گزینه نباید برای مسافر خارجی نمایش داده شود).
    - نمایش تقویم با فرمت **میلادی** برای تاریخ تولد.
- این تغییر وضعیت (نمایش/مخفی) باید به صورت آنی (Real-time) پس از انتخاب ملیت در فرم اعمال شود.
